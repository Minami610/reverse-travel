# reverse-travel（みちどころ ―近くの未知の場所を探そう―）

アプリの名前は「**みちどころ**」（2026-10-24、51本目でMinami決定。「未知」「道」「見どころ」を合わせた造語。旧称：逆引き旅行アプリ・いけるとこまで旅行）。
リポジトリ名・公開URL（reverse-travel）は変えない。

「出発駅と予算を入れると、その予算内で公共交通機関だけで行ける**知られていない景勝地**を返す」アプリ。

- 静的サイト＋事前生成JSON（バックエンドなし、GitHub Pages）
- 公開URL: https://minami610.github.io/reverse-travel/ （main branch / `docs` フォルダ）
- 交通手段は公共交通機関のみ（バス＋電車）、日帰り前提、予算の定義は**交通費のみ**

## 【設計原則】予算の上限が低いことは仕様であって制限ではない

- **予算は「往復」の交通費**（2026-09-12決定）。日帰りアプリなので帰りも含めないと嘘になる。片道基準だと「¥1000で行ける」と言われた人が実際には¥2000使う。
- **レンジは ¥200〜¥2000。上限は往復¥2000（2026-10-06 Minamiさんの判断）。これ以上は上げない。**
  上限は元々¥1000だった。¥2000への変更は「結果が少ないから上限を上げる」という場当たり的な改善ではなく、
  ビルド側の切り捨てが無いこと（fare-lookup-tables.json・route-details.jsonは元々運賃の上限なしに全件を
  保持しており、¥2000への拡大はフロントエンドの表示範囲を広げるだけでビルド側の変更・サイズ増加が
  一切不要なことを実測で確認済み）と、検索結果を「予算の帯」で表示する仕組み（直下）をセットで
  Minamiさんが検討したうえでの判断（詳細はgit logの同日コミット参照）。**この¥2000という上限を、
  今後さらに「結果が少ないから」という理由だけで上げてはいけない。** ¥3000〜¥5000あれば安い夜行バスで
  大阪から四国まで行けてしまい、企画が成立しなくなる。このアプリの価値は「**休日に小銭で行ける、近所に
  ある、地元の人すら知らなかった場所**」を出すことにある。遠くへ行くためのアプリではない。
- 到達範囲が狭いのは欠点ではなく、コンセプトを守るための制約。結果が少ない地域への対処は、上限の引き上げ
  ではなくスポット側の拾い方（除外の見直し、停留所からの距離の許容範囲）で考える。
- **「交通空白地では結果が0件になるのでは」という心配は不要。** 検索の出発点は必ず駅・停留所であり、公共交通が一切ない場所には人が住んでおらず、そこから検索する利用者もいない。このアプリは公共交通がある場所で使われる。
  **ただしこれは「駅そのものが交通空白」なケースの話であり、「駅は実在するが運賃改定等で帯の範囲に収まらなくなった」ケースは別**。実際に2026-10-01のことでんバス運賃改定でＪＲ栗林駅から往復¥400の検索が0件になった（最低片道運賃が¥200→¥210になり、往復¥400を超えたため）。これは実データを正直に反映した結果であり、**この場合も予算の上限・刻み幅は変えない**（上記のとおり仕様）。フロントエンド側で、帯の中が0件のとき結果がある上下最寄りの帯をボタンで案内する対応のみ行う（`main.js`の`buildNoResultsMessage()`・`findNearestBudgetsWithResults()`参照）。
- **検索結果は「予算の帯」で表示する**（2026-10-06決定、CLAUDE.md旧版の「予算以下すべてを表示」から変更）。
  表示するのは往復運賃が「予算−¥200より高く、予算以下」の場所だけ（例：往復¥1000なら¥801〜¥1000）。
  これは「大きい金額で検索して地図を見るだけのアプリ」になることを避け、並び替え（安い順・近い順等）が
  帯の中で意味を持つようにするための変更。乗換の到達も、乗換2区間の合計往復運賃で帯を判定する
  （`fare-calculator.js`の`roundTripFare`が既に直行・乗換とも合計往復額を持つため、帯判定に特別な
  分岐は不要）。

## コンテスト応募条件（最重要の制約）

**公共交通オープンデータチャレンジ2026**（応募開始 2026-10-01、締切 2027-01-11）に応募予定。

- **条件は「公共交通オープンデータセンターやGTFSデータリポジトリで公開されている公共交通オープンデータを『利用すること』」。**
  これは**満たすべき条件であって、排他条件ではない**（2026-09-12の開発者ウェビナーで確認）。
  他のデータソースの併用は禁じられていない。前例：昨年審査員特別賞の「東京終電マップ」は18事業者中5社をODPT外の公式サイトから手作業で取得している。「コミバスをつくろう」もOpenStreetMapと国勢調査を併用。
  よって **ことでん直取得を併用しても応募資格は失われない**（以前は「応募不可」と誤解していた）。
  ただし主たるデータ源は **gtfs-data.jp API v2** とし、**どのフィードがどこ由来かは出典表示で正直に列挙すること**。
- **応募成果物はチャレンジ開催期間中、誰でも無償で利用できる状態で公開が必須**（GitHub Pagesで充足）。
- 国土地理院はオープンデータ・パートナーであり、地理院タイルの使用は加点要素。
- **応募手続きは2段階**：①開発者サイトでユーザ登録（承認に2営業日）→ ②開発者サイトのトップから**チャレンジ2026にエントリー**（別操作）。**両方とも完了済み**（2026-09-12確認）。作品提出フォームは10月1日以降に表示される。
- **締切は 2027年1月11日(月・祝) 23:59 JST。提出後は修正不可。**ただし提出前は下書きを保存して何度でも修正できるので、早めに下書きを作っておくこと。
- **ODPTのアクセストークンは2種類ある**（1つではない）
  - CC0 / CC BY 4.0 / CC BY 2.1 JP / ODC BY 1.0 / ODbL 1.0 のデータ → **トークン不要**。APIのURLをそのまま使う
  - 「公共交通オープンデータ基本ライセンス」のデータ → **ODPTセンター用アクセストークン**
  - 「チャレンジ2026限定ライセンス」のデータ → **チャレンジ2026専用アクセストークン**（別物。期間中のみ有効）
- **gtfs-data.jpのフィードを実際に取り込むかどうかは`config/license-allowlist.json`の`allowed_license_substrings`（部分一致）で機械的に決める**（`scripts/build-pipeline/license-check.js`）。
  未設定・不一致のフィードは安全側に倒して除外する。**2026-10-07、全国棚卸しで「CC BY 2.1 JP」ラベルの稼働中フィードが新潟2・長野4・愛知1・兵庫32・熊本1の計40件（廃止済みを含めれば52件）、
  許可リストに無いという理由だけで除外されていたことが判明し、Minamiさんの承認を得て追加した。**
  CC BY 2.1 JPは「表示のみ要求」のCreative Commons Attributionの日本版2.1（4.0の前身、NC/ND/SA等の制限無し）で、
  サンプル確認（新潟県上越市・兵庫県赤穂市の`feed_license_url`が両方とも`https://creativecommons.org/licenses/by/2.1/jp/`）でも裏取り済み。
  一方、`"CC-BY"`（バージョン表記なし、静岡県掛川市の2フィードのみ）は未追加（要確認のまま）。
  掛川市自身のオープンデータ利用規約ページを確認すると実際の運用ライセンスは「CC BY 4.0」だが、gtfs-data.jp側のラベルが省略表記になっているため、
  機械的な部分一致では拾えない。追加するかはMinamiさんの判断待ち。
- **「その筋屋」の注意書きの扱い（2026-10-13決定：A）**：GTFS変換ソフト「その筋屋」で作成されたフィードの一部は、`feed_version`欄に
  利用条件の注意書きがそのまま入っている。対象は7件（富山地方鉄道バス・加越能バス×3・滑川市コミュニティバス「のるmycar」・
  小矢部市営バス・白山市コミュニティバス「めぐーる」）。原文の例（富山地方鉄道バス）：
  > 2026/09/30 16:13:02 （GTFS出力日時） 付加情報：20261001_2026年10月01日（富山地鉄バス R8.10.1運賃改定 ぶりかにダイヤあり） その筋屋 2.510
  > 【日本バス情報協会の関係者・支持者は利用禁止。GTFSデータリポジトリへのCCライセンスでの登録禁止】
  > https://gtfs-jp.org/bus/ ※一般のバス利用者への案内利用はバス会社に公開許可を得ましょう。

  **データは使い続ける**（Minami決定）。理由：7件とも事業者自身がgtfs-data.jpにCC0／CC BYで登録しており、
  公開・利用を認めていると読める。「その筋屋」側の注意書きは変換ソフトの配布元が一般のバス情報サイト運営者等に
  向けて書いたもので、フィード自体のライセンス（事業者が選択）を上書きするものではないと判断した。
  `config/license-allowlist.json`・`license-check.js`の除外判定ロジックは変更していない（ライセンス自体は
  CC0/CC BY等で許可リストに最初から一致しており、この注意書きが取り込み可否の判定に影響したことは無い）。
  **画面には短い版名だけを出し、原文は出さない**（`formatFeedVersionShort()`、`assets/js/main.js`。
  `data-sources.json`自体のfeed_versionは変更していない＝表示だけを短くする）。実装・テストは18本目で対応。
  **新しくデータを加えるときは、同じような利用条件の文がfeed_version等に紛れ込んでいないか確かめること。**
- **ODPTが活用を推奨している「連携オープンデータ」**：e-Stat（政府統計・国勢調査）、国土地理院 基盤地図情報、G空間情報センター、国土交通データプラットフォーム、歩行空間ネットワークデータ、PLATEAU、Project LINKS、気象庁、警察庁交通事故統計など。
- **今後の拡張案は `IDEAS.md` にまとめてある**（e-Statによる交通空白の可視化、ダイヤ改正への自動追従、ODPT鉄道データ、チャレンジ限定ライセンスのデータ等）。**いずれも未着手で、全国版の完動が前提。** 余力ができたとき、または方向性の相談を受けたときだけ参照すればよい。
- **AIによる開発は制限なし。コンテスト以前から開発していた作品の提出も可。**
- 審査の詳細基準は非公開（事務局が公平性を理由に明言）。
- **審査員に草薙昭彦氏（Mini Tokyo 3D 作者）が入っている。** 同氏は過去の講評で「オープンソースで公開された点」が評価されたと述べ、応募者への助言として「GitHubにあげ、**ライセンスを明示し**、ドキュメントを整える」「共通言語（GTFS）に乗せる」を挙げている。**MITライセンスの明示とREADME整備は加点材料。**
- **差別化の糸口**：東京終電マップが自ら積み残しとして挙げたのが「ダイヤ改正でデータが陳腐化する。自動更新が次の課題」。本アプリは gtfs-data.jp API からカタログを取得する設計のため**自動更新が構造的に可能**。実装すれば明確な強みになる。
- ODPTには「チャレンジ限定ライセンス」で提供されるデータがあり、今年度も新規データ公開が予定されている。デマンド交通・駅構内・歩行空間ネットワーク等。利用時は応募と期間中の無償公開が必須条件。
- **アプリに必須の表示3点**（未実装なら最優先で実装すること）
  1. データの出典（公共交通オープンデータセンター／gtfs-data.jp提供である旨。CC BYのフィードは各公開元も明記）
  2. データの正確性・完全性が保証されていない旨
  3. 開発者の問い合わせ先（交通事業者へ直接問い合わせないよう促す一文を含む）
- 審査基準：①社会課題解決 ②オープンデータ活用のインパクト ③技術的完成度 ④UI/UXの完成度。
  **都道府県のカバレッジ数は②にしか効かない。半分壊れた全国版は③④を直撃する。カバレッジより完動を優先する。**
